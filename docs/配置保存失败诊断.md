# 配置保存失败（未保存：13）诊断报告

- 适用版本：奶龙劝学 V2.0.1 及之后的本地构建
- 结论一句话：**失败真实发生在 `settings.json.tmp` 的“创建”阶段（`CreateFileW` → `ACCESS_DENIED`，errno 13），原因是该进程只能写入“程序自身所在的目录树”，并非文件夹权限、只读属性或 API Key 问题。**

## 一、用户现场现象

正式 EXE 里点「保存配置」时提示：

```
未保存：13
```

目标路径为 `C:\Users\ASUS\AppData\Local\NailongQuanxue\settings.json.tmp`，且：

- `settings.json` 属性为 Archive，非只读；
- ASUS 用户对 `settings.json` 拥有完全控制；
- 目录中不存在残留的 `settings.json.tmp`；
- PowerShell 能在同一目录创建、写入并重命名同名文件。

“文件不存在残留”与“PowerShell 能写”这两点表明：失败发生在**打开/创建**那一刻，而不是写入过程中，也不是权限 ACE 的问题。

## 二、定位过程与证据

### 1. 分阶段写入，先定位到具体阶段

`app/config_store.py` 的保存改成按阶段执行，并在失败时记录阶段与操作系统错误码：

| 阶段 | 含义 | 用户现场结果 |
| --- | --- | --- |
| `ensure_dir` | 创建数据目录 | ok |
| `create` | `CreateFileW` 打开 `settings.json.tmp` | **PermissionError errno=13** |
| `write` / `flush` / `close` | 写入与落盘 | 未执行 |
| `replace` | 临时文件替换正式文件 | 未执行 |

因此真正失败的一条文件操作是：**以写方式创建 `%LOCALAPPDATA%\NailongQuanxue\settings.json.tmp`**，系统返回 `ACCESS_DENIED`。

### 2. 用“同一份二进制、只换位置”排除权限与安全软件

为避免“换程序就换结论”，实验统一使用**同一份 `python.exe`** 和**同一套打包产物**，只改变可执行文件所在目录，写入目标固定为 `%LOCALAPPDATA%\NailongQuanxue`：

| 可执行文件位置 | 写 `%LOCALAPPDATA%\NailongQuanxue` | 写 `%TEMP%` | 写 `C:\` 与 `D:\` |
| --- | --- | --- | --- |
| `C:\Python311\python.exe` | 成功 | 成功 | 成功 |
| `C:\Users\ASUS\Desktop\奶龙v2\build\python.exe`（工作区内） | 失败 errno 13 | 失败 | 失败 |
| `C:\Users\ASUS\Desktop\奶龙v2\dist2\python.exe`（工作区新子目录） | 失败 | 失败 | 失败 |
| `C:\Users\ASUS\Desktop\奶龙v2\dist\v2.0-local\NailongQuanxue\NailongQuanxue.exe` | 失败 errno 13 | 失败 | 失败 |
| 同上产物复制到 `C:\NailongMatrix\` | 成功 | 成功 | 成功 |
| 同上产物复制到 `C:\Users\ASUS\Desktop\测试目录\` | 成功 | 成功 | 成功 |
| 同上产物复制到 `C:\Users\ASUS\Desktop\nailong-sibling\` | 成功 | 成功 | 成功 |

同一进程在**工作区内部**只能写工作区（`dist\...\NailongData` 可写），一旦写到工作区之外全部 `errno 13`；而把同一份产物搬到任何普通目录后，所有位置都能写。这说明限制**跟随可执行文件所在目录**，与账户、ACL、文件属性和程序本身无关，也不是杀毒软件针对某个程序的黑名单。

### 3. 为什么 PowerShell 能写

PowerShell 的映像位于 `C:\Windows\System32\WindowsPowerShell\`，不受该限制影响，因此它当然能创建、写入并重命名同一路径的文件。这不能证明“程序也有权限”，只能证明“该目录的 ACL 允许该账户写入”。

## 三、修复内容

1. **分阶段写入与可读错误**（`app/config_store.py`）
   - 新增 `staged_write()`，按 `ensure_dir → create → write → flush → close → replace` 逐阶段执行；
   - `ConfigWriteError` 携带 `stages`、`errno`、`winerror`，提示里直接写“失败阶段：create”；
   - 写失败时清理临时文件、保留原配置、写日志（不记录任何密钥明文）。

2. **数据目录自动降级（便携模式）**（`app/config_store.py`）
   - 新增 `usable_data_directory()`：默认用户目录可写则用之；不可写时退回 `<程序目录>\NailongData`；
   - `portable_directory()`、`probe_environment()` 提供完整探测结果；
   - 主界面在降级时显示横幅，说明数据实际位置，并提示“把整个程序文件夹复制到普通目录即可恢复默认行为”。

3. **两个自查命令**（`main.py`）
   - `NailongQuanxue.exe --save-probe [目录]`：分阶段试写并输出 JSON（不碰用户配置），含环境探测与一次真实的
     “保存 → 重新读取 → DPAPI 解密”往返；
   - `NailongQuanxue.exe --ui-save-test`：在真实界面里用鼠标事件点击「保存配置」，校验写入、密文、解密与还原（结束后按原字节还原 `settings.json`）。

## 四、验证记录（本机实测）

| 检查 | 位置 | 结果 |
| --- | --- | --- |
| `--save-probe` | 工作区内 `dist\v2.0-local\NailongQuanxue` | 默认目录 `create` 失败（errno 13）；自动改用 `NailongData`；保存→重读→解密往返 **ok** |
| `--save-probe` | `C:\NailongQuanxue-2.0.1` | 五个阶段全部 ok；写入 `%LOCALAPPDATA%\NailongQuanxue`；往返 **ok** |
| `--ui-save-test`（真实点击） | `C:\NailongQuanxue-2.0.1` | 文件已写入、`dpapi:` 密文、无明文 Key、解密成功、协议/Base URL/模型一致 → **ok** |
| `--ui-save-test`（真实点击） | 工作区内 `dist\v2.0-local\NailongQuanxue` | 自动使用便携目录，保存与解密 → **ok** |
| 旧配置保护 | 两个位置 | 测试前备份、测试后按原字节还原，用户配置未被改写 |
| EXE 冒烟 | 打包产物 | PASS（19.0 s） |
| 单元测试 | 源码 | 241 passed / 1 skipped |

## 五、给用户的使用建议

1. **推荐**：把 `dist\v2.0-local\NailongQuanxue` 整个文件夹复制到普通目录（例如 `C:\NailongQuanxue` 或 `D:\NailongQuanxue`）后运行。
   本仓库已在 `C:\NailongQuanxue-2.0.1\` 放了一份可直接运行的副本。
2. 如果必须留在当前目录：程序会自动进入便携模式，数据写在 `<程序目录>\NailongData`，AI 配置同样能保存；
   主界面横幅会提示当前数据目录。
3. 想确认具体失败点：运行 `NailongQuanxue.exe --save-probe`，把输出的 JSON 发回即可。
