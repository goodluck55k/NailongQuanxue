日期：2026-10-30（本地 Windows）；结论：**P1 未通过，暂不具备进入 P2 的条件**。已验证本机 Qt 录制与本地解码的基本路径；真实音频 API、参考音轨人工判断、音画同步精度及打包后录制尚未完成。未上传任何媒体，未调用收费 API，未修改 V1.1 业务代码。

## 基线与范围

仓库为本地 main，HEAD `f5b8a1fb12bfe753bcd6ab1c4acc9086b74bce5b`；Python 3.11.5、PySide6 6.8.3、pytest 8.4.2、PyInstaller 6.16.0。阅读 V2 指南与现有应用代码。实验代码独立于 app：`p1_experiments/capture_probe.py`、`p1_experiments/extract_audio.py`。结果和本机实验媒体在 Git 忽略目录 `build/p1-local/`，不用于提交或发布。V1.1 计时、强制休息、紧急退出、素材、依赖及打包脚本没有改动。

## 实际验证通过

1. `python p1_experiments/capture_probe.py`：Windows 本机检测到 2 个摄像头和 1 个音频输入；默认设备可在同一 QMediaCaptureSession 同时接入 QCamera、QAudioInput、QMediaRecorder。Qt 报告 MP4/H.264/AAC 编码支持。录制状态经历 RecordingState、StoppedState，无报告的录制或回放错误。文件 8,722,593 字节，容器时长 9.984 秒；录制 duration 9.952 秒。解码得到 296 个有效视频帧、443 个音频缓冲；视频轨 1920×1080，音频轨 48 kHz 双声道 AAC。未人工确认画面内容或听辨音频；帧有效和采样非零并不证明真实画面或清晰人声。
2. 录制后摄像头状态为 inactive；独立重新打开摄像头并检查 active 成功。无任何音视频输入时调用录制，收到 `No video or audio input` 错误。未验证麦克风独占释放或设备热拔插。
3. `python p1_experiments/extract_audio.py`：Qt QAudioDecoder 将该 MP4 音轨解码到 16 kHz、单声道、16 位 PCM WAV，151,194 样本，约 9.450 秒；峰值 1004、RMS 105.9（16 位采样值），证明解码信号非全零，但不证明是清晰笑声。输出音频只在本地。
4. `python -m pytest -q`：135 通过、0 失败、1 跳过（私有旧图片按公开源码设计缺失），6.32 秒。V1.1 测试通过不等于 V2 网络取消和托盘集成已验证。
5. 固定参考视频存在，V1.1 基线核对其 SHA-256 与清单一致；此前 Qt 解码日志确认 AAC 音轨。V1.1 的休息播放器不接音频输出，实验未改变它。

## 失败与异常

- 首次提取实验使用 `QAudioDecoder.errorOccurred`，PySide6 6.8.3 无该属性，出现 AttributeError；改用 `error` 信号后提取成功。保留此事实以便复现。
- 提取音频样本长 9.450 秒，容器显示 9.984 秒，差约 0.534 秒。尚未确定原因，可能涉及采集启动、轨道时间戳或解码；不能以容器总时长代表可分析音频长度，也不能据此断言音画精确同步。需用有明确视听同步标记的样本测偏移与漂移。
- 在无输入测试中获得设备缺失类错误；这不证明无权限、设备拔出、磁盘满、目标不可写或慢速编码收尾均已正确处理。

## 技术选型建议（待真实验证）

- **API**：使用按协议显式选择的适配器，配置 Base URL、Model ID、Key 引用；每种协议分别实现请求格式、认证、音频格式、结构化输出、错误映射，不按域名或所谓兼容性猜测能力。HTTPS 默认，明确展示目标域名，Key 使用 Windows Credential Manager 或 DPAPI，不进入源码、日志或报告。连接测试和用户明确同意的音频能力测试分开。音频上传只发必要音轨，限制大小、时长和超时；不自动无限重试计费请求。记录脱敏的请求 ID、耗时及供应商实际返回的用量，估算费用需使用当时该服务的定价。
- **能力差异**：例如 Gemini 官方文档描述音频输入和非语音声音理解，另有结构化输出接口；这只是文档能力，不证明任何特定模型对笑声时长准确，也不保证它与其他供应商请求协议相同。严格 JSON Schema 能约束形状，不能保证语义正确。
- **音频链路**：优先采用同一次录像 MP4 内音轨，停止后等待录制完成和文件稳定，再使用 QAudioDecoder 解码；适配器按服务商要求选择 16 kHz 单声道 PCM WAV 等格式。先校验实际样本数、时长、空轨和信号质量，避免将静音、截断或异常文件当成功。应保留原始轨道时间戳和偏移用于对齐，不把本次重采样结果误当完整时间轴。
- **累计笑声**：让已验证模型返回基于音频时间轴的起止片段，客户端严格校验数值有限、0 ≤ start < end ≤ 实际音频时长；裁剪/合并交叠片段避免重复计时，过滤短于待验收阈值的片段，再求并集时长。示例试验起点为 10 秒录制、1 秒有效片段、累计 4 秒，均不是已批准性能标准。无区间、模糊结果、错误、过期 token、超时均为未通过；必须用获许可的笑声、讲话、喊叫、静音等正反例人工标注测试，验证时间精度和误判，不能将模型自由文本当业务指令。
- **录像**：优先继续评估当前 PySide6 的 QMediaCaptureSession + QCamera + QAudioInput + QMediaRecorder，节省额外采集依赖。必须在工作线程/异步边界管理网络、取消与过期结果；Qt 对象线程归属及录制收尾须专门测试。`stop()` 后等待 StoppedState 并验证可读文件，不靠固定延时作为正式完成保证；注意设备慢驱动不能阻塞撤下遮挡。
- **新增依赖**：本次实验不需要新依赖；未来 HTTP 客户端、Windows 安全凭据接口及协议 SDK 需按实际适配选择并锁版本。QAudioDecoder 能完成本次提取，暂不建议仅为提取就增加 FFmpeg 可执行文件；如后续需 ffprobe、可靠时间戳或更广编码能力，评估额外体积和许可证。
- **体积与性能**：本机 10 秒样本约 8.3 MiB，1920×1080，视频流约 6.86 Mbps，码率与设备、编码器及场景有关；长录制、内存缓冲、转换和并发上传均可能增加磁盘、CPU、延迟及 API 成本。不能把本次数值视为所有设备指标。

所有轨道 metadata start_time 为 0；视频首包 PTS/DTS 为 0；表中各末包 DTS 与 PTS 相同。音频首个负时间包与 AAC 编码预滚有关，不能直接算成音画不同步。原录音的音轨自身时长就是 9.45 秒，WAV 解码的 9.450 秒与之相符，故差值**不是 WAV 提取造成**，也不是仅有容器显示值不同：文件中音轨结束时间确实早于视频。四次补充录制均复现，幅度不恒定。

可确认的直接原因是 Qt/设备采集与封装生成了较短音频轨；无法仅凭轨道时间戳确定真实声音是在开始丢失、停止时截断，还是采集时钟/设备启动和时间戳归一化造成。没有把负首包或末端差值当作实测同步偏移。尚未证明底层根因，也未通过补静音或修改元数据掩盖。原实验 `capture_probe.py` 在调用 stop 后立即解绑、固定延时再读取，存在潜在收尾风险；补充实验监听到 `StoppedState` 后才在下一事件循环释放并检查，差异仍存在。状态信号和文件可解析不证明所有设备的编码收尾均已可靠完成。

### 可观察同步与设备

尝试以拍手作为同一事件，采集三段实机录像并查看局部帧及音频能量；未能从画面与音轨中可靠配对清晰接触瞬间及声峰，因此**无有效音画偏移数值**，不能宣布同步通过或失同步。下一步需在画面中央清晰拍手或使用有同步声光标记的可重复工具，同时记录首尾事件，测偏移及漂移；这与轨道长度差是不同问题。

三次连续录制均收到 RecordingState 和 StoppedState、无录制错误，随后摄像头 inactive，下一次摄像头与麦克风均可再次录制；另用 QAudioSource 在录像后读取 768000 字节音频、NoError，停止后 StoppedState。此结果支持本机设备可复用，不证明 Windows 独占模式、拔出、驱动崩溃或其他硬件均可靠。

无真实设备的不可写路径实验得到 `Cannot open the output location for writing`，目标文件未产生；原 P1 无输入测试得到 `No video or audio input`。真实设备热拔插、权限撤销、录制中磁盘满、部分文件损坏及故障后恢复未测；不能由单一写入失败证明所有失败文件均被清理。本次实验不触碰或删除既有媒体。

### 本地打包实验

使用 PyInstaller 6.16.0 构建隔离的 `repeat_capture.py`，输出 `build/p1-package/dist/P1CaptureProbe`，目录约 141,545,607 字节；在同一台 Windows 机器运行 EXE，录制出 5,951,477 字节 MP4，含 H.264 与 AAC，停止信号正常，两轨可用 FFmpeg 解码，轨道时长差约 0.4318 秒。视频原始包 DTS 单调递增；FFmpeg 向 null 输出时出现非单调 DTS 提示，需进一步定位输出时间基和播放兼容性。此为实验程序，非正式应用构建；未在干净机器或其他 Windows/摄像头/声卡组合验证，未发布。
